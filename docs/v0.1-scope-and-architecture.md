# Windows 中文 TXT 阅读器首版范围与技术方案

更新日期：2026-10-25。用户已确定首发 Windows 桌面版，主要阅读中文 TXT 小说；首版必须同时支持分页和滚动，并可自由切换。

建议首版采用 C#、.NET 10 LTS、WPF 和 SQLite，围绕“导入一本小说，舒服地读，关闭后可靠续读”完成完整流程。以下功能边界和实现选型是方案建议，尚未开始编码。首发验证环境建议为 Windows 11 x64；其他 Windows 版本和 ARM64 的支持范围在发布前另行验证。

首版功能按下面的具体行为验收。

| 模块 | 首版范围 | 完成标准 |
| --- | --- | --- |
| 本地导入 | 文件选择、拖拽 TXT、同批多个文件；默认复制到应用书库，原文件只读 | 导入后原文件移动不影响阅读；同内容文件去重；失败项能看到原因 |
| 中文编码 | UTF-8、UTF-16 LE／BE、GB18030／GBK、Big5；自动检测、手动重选及预览 | 常见简繁中文样本正确；检测失误可修正；异常字节不悄悄丢弃 |
| 章节目录 | 自动识别卷、章、序言、番外等；目录搜索、前后章跳转；预设识别规则切换和重新生成 | 无标题也能阅读；正文里的“第十章”不能随意当标题；重建目录不改正文或丢进度 |
| 分页阅读 | 单栏、单页静态排版；上一页／下一页；到章末继续读下一章 | 按实际字体、宽度和高度分页，整行显示，页间无漏字或重叠；支持回翻 |
| 滚动阅读 | 上下滚动；鼠标滚轮、键盘和按屏移动；跨章节连续衔接 | 阅读无需逐章手动退出；加载与回收附近内容时文字不突然跳动 |
| 模式切换 | 分页与滚动随时切换；为每本书保存选择 | 切换前的阅读锚点仍出现在当前视口；新排版后的锚点位置可解释，不要求像素坐标不变 |
| 排版与主题 | 系统字体、字号、行距、段距、首行缩进、阅读宽度；浅色／深色／米色主题 | 设置实时生效，调整窗口和 DPI 后正文仍清晰；中文标点和中英混排不发生截字 |
| 阅读进度 | 自动续读、全书百分比、当前章节、进度跳转、最近一次跳转返回 | 字号、窗口和阅读模式变化后仍回到原文位置；每本书独立保存 |
| 搜索与书签 | 全书文字搜索、结果片段、点击定位、高亮；添加／删除书签；文本选择复制 | 可搜索一字、两字人名和跨读取块的词；从搜索位置可返回原阅读位置 |
| 简单书架 | 列表视图、最近阅读、书名筛选、进度展示、改书名、移出书架 | 能找到、继续读和整理已导入的书；移出书架只影响应用副本和本地记录 |
| Windows 操作 | Ctrl+O 打开、Ctrl+F 搜索、F11 全屏、前后页／章快捷键、置顶开关、记住窗口尺寸 | 输入搜索文字时不会误翻页；显示器布局改变后窗口仍能找回 |
| 数据与交付 | 手动备份／恢复书库、进度、书签和设置；自包含免安装包 | 在没有 .NET 开发环境的干净 Windows 机器上运行，备份能恢复到新目录 |

界面建议保持两层：书架用于找书，阅读页用于看书。阅读页左侧是可收起的目录／搜索／书签栏，中间是正文，底部只展示章节、百分比和模式切换；排版设置放到独立面板。首次阅读暂定分页，每本书之后沿用上次选择。版式设置先采用全局默认，逐书保存阅读位置和阅读模式。

正文只做必要的换行规范化。首行缩进和段距属于显示设置；自动合并断行、广告净化、繁简转换会影响原文与位置对应，放在体验增强版本一起设计。首版也暂缓自动滚屏、听书、云同步、AI、EPUB／PDF、复杂笔记、书源、透明窗口、全局隐藏热键、统计和自动更新。双模式已经是首版范围，不再作为后续功能推迟。

技术选型的比较如下。适用性是基于本项目范围的判断，不是对这些框架的性能排名。

| 方案 | 能解决什么 | 本项目的主要代价 | 建议 |
| --- | --- | --- | --- |
| C#／.NET 10／WPF | 一套 C# 代码处理文件、界面和数据；原生文本、字体和窗口能力；FlowDocumentReader 提供分页与连续滚动 | WPF 限于 Windows；长篇正文需要自己管理分段加载和位置映射；以后跨平台需重做界面 | 首选 |
| Tauri 2／TypeScript 前端／Rust | 网页界面和 CSS 排版、可复用跨平台桌面框架 | Windows 依赖 WebView2；需要维护前后端边界；分页、虚拟滚动和锚点恢复仍需设计 | 若跨平台很快成为明确目标，再优先考虑 |
| Electron／TypeScript | 网页技术栈、统一的 Chromium 运行环境、成熟的桌面生态 | 随应用携带 Chromium 和 Node.js；发布和运行成本对纯 TXT 功能需要额外权衡 | 暂不选作首版默认方案 |

WPF 的 Windows 限制见[官方概览](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/overview/)，分页与滚动见 [FlowDocumentReader 文档](https://learn.microsoft.com/en-us/dotnet/api/system.windows.controls.flowdocumentreader?view=windowsdesktop-10.0)。Tauri 的 Windows 环境依赖见[先决条件](https://v2.tauri.app/start/prerequisites/)，Electron 的运行时组成见[官方介绍](https://www.electronjs.org/docs/latest/)。截至调研日，.NET 10 为 LTS，官方支持截止日为 2028-11-14，适合新项目采用并持续更新补丁。[.NET 支持政策](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core)。

建议使用少量明确的组件，避免首版引入插件系统或复杂服务框架。

| 部分 | 选型 | 职责 |
| --- | --- | --- |
| 窗口与界面 | WPF、XAML | 书架、阅读页、设置和 Windows 操作 |
| 界面状态 | CommunityToolkit.Mvvm | 命令、属性通知和异步操作状态 |
| 正文展示 | FlowDocumentReader 及其分页／滚动视图封装 | 使用 WPF 排版；应用负责内容窗口、锚点和跨块导航 |
| 文本核心 | 独立 C# 类库 | 编码选择、正文索引、章节识别、搜索、稳定位置模型 |
| 编码兼容 | System.Text.Encoding.CodePages；UTF.Unknown 作为检测候选 | 标准库解码，检测库只提供编码建议，允许用户覆盖 |
| 数据存储 | SQLite、Microsoft.Data.Sqlite | 书架、版本、进度、书签、设置和结构版本 |
| 书籍与缓存 | 本地文件 | 原始文件副本、规范化正文和可重建索引 |
| 验证与发布 | .NET 测试、Windows 集成测试、GitHub Actions | 核心回归、构建、打包和发布产物 |

[MVVM Toolkit](https://learn.microsoft.com/en-us/dotnet/communitytoolkit/mvvm/)、[Microsoft.Data.Sqlite](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/)、[CodePagesEncodingProvider](https://learn.microsoft.com/en-us/dotnet/api/system.text.codepagesencodingprovider?view=net-10.0) 和 [UTF.Unknown](https://github.com/CharsetDetector/UTF-unknown) 均有独立的官方或维护者文档。具体依赖版本在初始化工程时选择稳定版并锁定。

模块关系保持简单。界面和正文控件之间的适配代码留在 Windows 项目，解析与存储不依赖 WPF。

```mermaid
flowchart LR
    A[WPF 书架和阅读页] --> B[阅读会话与命令]
    B --> C[文本核心 编码 目录 搜索 位置]
    B --> D[本地存储 SQLite 与书籍文件]
    C --> E[正文分块和位置索引]
    E --> F[分页或滚动视图]
    F --> B
```

编码处理顺序为：优先识别 BOM，进行严格 UTF-8 校验，再结合检测库提供的候选，在支持的中文编码范围内选择。UTF-16 无 BOM 时只作候选，不能把任意偶数字节强行当作正确 UTF-16。编码不确定或出现非法字节时提供解码预览和手动选择；选择结果逐书保存。用户确认用替代字符继续时保留原始字节副本，便于以后重新解码。

正文存储保留导入时的原始字节副本，另生成统一换行后的正文快照。原始文件哈希用于相同导入去重，正文快照有自己的版本标识。目录、搜索、进度和书签都引用同一正文版本。重新选编码会产生新正文版本，尝试用附近文字迁移位置；不能可靠迁移时明确提示，避免静默跳到错误内容。更换版本的小说先视为新的导入，不在首版自动合并。

阅读位置建议采用 `书籍 ID + 正文版本 + 正文 UTF-16 偏移 + 前后文片段`。偏移统一指 .NET UTF-16 代码单元，切块和定位不得拆开代理项或组合文字。章号、分页页码和滚动像素只作为当前显示信息；字号或窗口变化后重新排版，用正文位置找到新页或滚动位置。FlowDocument 的 TextPointer 偏移还包括结构符号，不能直接当作正文偏移，须通过 Run／Paragraph 与正文索引的映射转换。

两种阅读模式共用上述位置与内容模型。分页模式记录本页正文起止位置，连续翻页和回翻使用缓存的分页边界；字体、宽度或 DPI 变化后使相关布局缓存失效。滚动模式记录首个可见正文位置及视口内偏移。切换时先保存锚点，再完成新布局并恢复锚点；验收以同一正文位置仍可见为准。书籍整体进度按正文位置计算，首版不在改字号时强制重新计算整书总页数。

长篇采用按需加载：索引覆盖全书，界面只保留当前及附近的正文范围。优先以章节和段落为边界，异常长章或长段再分块；块边界不能改变正文内容或新增段落语义。滚动接近边界时预加载下一段并回收远处内容；分页在当前范围附近计算布局并预取后续页。解析、索引和搜索放到后台，WPF 对象创建和视图更新保持在 UI 线程。

WPF 的 UI 虚拟化不等于正文数据虚拟化，官方说明控件不内置通用数据虚拟化能力。因此，“用了 FlowDocumentReader”不能视为长篇性能已经解决。正文分段、跨段连续性、选区复制和锚点恢复是开工后必须先通过的技术验证项。[WPF 控件性能说明](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/advanced/optimizing-performance-controls)。

搜索首版使用后台分块扫描，按原文做字面匹配，分批返回结果并支持取消；相邻读取块保留足够重叠以避免漏掉跨块词语，结果去重。不要只使用 FlowDocumentReader 的内置查找，因为它只覆盖已装载的内容。暂不引入全文检索分词系统：SQLite FTS5 的 trigram 全文查询对少于三个 Unicode 字符的匹配有限制，而两字人名是本项目的主要搜索场景。后续确有跨书检索需求再评估专门索引。[SQLite FTS5 说明](https://www.sqlite.org/fts5.html)。

应用数据建议放在 `%LOCALAPPDATA%\<应用名称>\`，书籍副本和缓存分目录，SQLite 保存结构化记录。进度写入采用串行队列，约每 2 秒定期提交最新值，翻页／跳转后合并提交，关闭书籍和正常退出时刷盘；写入失败须提示，不能继续声称已保存。仅靠退出事件无法覆盖强制结束进程。Microsoft.Data.Sqlite 的异步方法实际可能同步执行，数据库工作应交给后台队列处理。[异步限制](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/async)。

备份导出书籍、阅读记录、设置和格式版本，恢复前校验文件完整性并在临时目录准备，成功后切换，失败不损坏现有书库。在线数据库使用 SQLite 备份接口建立一致快照；备份期间协调书库写入，不能直接复制正在写入的数据库文件当作可靠备份。[SQLite 备份接口](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/backup)。

开发顺序应先消除正文引擎风险，再扩展完整界面。每一步都有可检查的产物。

| 阶段 | 交付物 | 通过条件 |
| --- | --- | --- |
| 1 双模式技术验证 | 一个能打开样本的阅读窗口，分页／滚动／字号调整／位置恢复 | 快速切换与连续跨块阅读无漏字、重字、崩溃或明显跳动；确定分块窗口策略 |
| 2 文本与数据核心 | 编码、目录、全文搜索、书籍版本、进度和书签 | 中文样本与异常格式回归通过；重新打开和中断恢复可复现 |
| 3 首版完整交互 | 书架、目录、搜索、主题排版、快捷键、备份恢复 | 从导入到阅读、关闭、续读和恢复备份的流程跑通 |
| 4 发布验证 | 自包含 win-x64 包、说明、截图、构建流程与测试结果 | 干净机器安装或解压运行，路径与 DPI 场景通过；具备可复现的源码构建说明 |

代表性测试包括 UTF-8 有无 BOM、UTF-16 LE／BE、GB18030／GBK、Big5；CRLF／LF／CR；简繁中文、中英混排、生僻字、emoji；无目录、重复标题、超长章节和超长段落。阅读测试覆盖快速前后翻页、跨章滚动、反复切换模式、搜索跳转返回、调整字号和窗口、100%／150%／200% DPI、正常退出及强制结束后的续读。

性能用 10 MiB 和 50 MiB 小说样本验收正常阅读，100 MiB 样本用于压力测试；压力测试结果不自动扩大首版支持承诺。技术验证先记录首屏时间、翻页与滚动延迟、搜索时间和峰值内存，再确定发布阈值。应在普通 CPU、8 GB 内存和 SSD 的 Windows 机器或受限虚拟机上复核，不能只以开发主机结果作为标准。每份结果注明样本、机器和首次／再次打开条件。

发布建议从自包含 ZIP 开始，用户解压后可直接运行，应用仍将数据放在 LocalAppData；带运行时的包体大小以构建实测为准。后续安装包和文件关联可单独增加。自包含发布能够携带 .NET 运行时，目标机器无需预装该运行时。[.NET 发布说明](https://learn.microsoft.com/en-us/dotnet/core/deploying/)。GitHub 发布前补齐项目许可证、README、构建步骤、问题模板和第三方声明；此方案不代替正式的许可证选择。
